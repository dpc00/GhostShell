**ROOT CAUSE FOUND (2026-10-10, night, after the Sublime restart):** two Windows ConPTY effects, both proven with a raw listener script (probe.py / probe2.py, scratchpad, not in the repo). (1) ConPTY silently DROPS any OSC sequence written to a program's input: plain `ESC ] 7501 ; ? ESC \` never arrives, the same string sent as win32-input-mode key events (`ESC [ 0;0;<ord>;<1|0>;0;1 _` per character, down and up) arrives intact; CSI and DCS replies pass. (2) ConPTY answers DA1 and the DECRQM queries ITSELF in about 1 ms, so the DA1 answer (`?61;6;7;21;22;23;24;28;32;42c`) always reaches the program BEFORE GhostShell's XTVERSION, `?u` and 7501 answers (which make a round trip through Sublime); Claude Code treats DA1 as the end of the questions, so those later answers count as "no reply" (log: `kittyKeyboard=no (no reply to CSI ? u)`, `no XTVERSION reply`, `programStatus=no`). Change made, UNCOMMITTED, in `ai_terminal.py`: `_ps_reply()` sends the 7501 reply as key events on Windows; proven the reply now arrives (3 probe runs). Claude Code still logs programStatus=no because of (2). Candidate fix for (2), NOT done: create the pseudoconsole with the passthrough flag (`PSEUDOCONSOLE_PASSTHROUGH_MODE` = 0x8, Windows 11 24H2+; this machine is build 26300) in `tools/agent_broker.py` line 296-297 (`self._conpty.create(..., 0, ...)`) so ConPTY forwards DA1/DECRQM to GhostShell's parser, which answers all queries in order. It affects every new tab (the running broker per tab keeps its flags), so test opt-in first, with fallback to 0 if CreatePseudoConsole fails. The same key-event trick would also let OSC replies like the OSC 11 colour query work.

**SOLVED (2026-10-10, night): Claude Code now sends OSC 7501 reports.** The passthrough flag was NOT needed: GhostShell already ships the Windows Terminal ConPTY (terminal/bin/conpty, tools/conpty_api.py), opt-in per profile. With it the startup answers come in Claude's order (XTVERSION, DECRQM 2026/1016 status=2, kitty `?0u`, our 7501 reply, DA1 last) and `claude --debug` logs synchronizedOutput=yes, kittyKeyboard=yes (flags=5), mousePixels=yes, programStatus=yes (probe: OSC 7501 reply). Changes (committed): new profile key `modern_conpty` (checked in `_with_conpty_folder`, ai_terminal.py) set to true on the "Claude" profile; `_ps_reply()` sends the 7501 reply as win32-input-mode key events on Windows (needed with the built-in ConPTY, harmless with the new one); omp profile no longer names a winpty folder inside the removed Python 3.12 (it had silently fallen back to the built-in ConPTY). Proven in the live Sublime with a real "Claude" profile tab: GhostShell recorded `state=idle:app=claude-code`, then `working`, then `done` after one prompt (`term.program_status_seen`). A tab opened from the Claude profile after the change is needed; the long-running Claude tab keeps the old ConPTY until it is reopened.
