**Why it happened:** Donald's Claude tab did not auto-close after `/exit`. He then ordered "test everything, kill, close, kill&close, detach, reattach ... and 4 different detach scenarios". There is no test suite (AGENTS.md rule 7a: he deleted `tests/` on 2026-09-21), so every case was run live through sublime-mcp on a cheap `PowerShell` profile (detachable) and checked against processes (broker pythonw + child) and the tab list.

**Matrix, all pass in the main Sublime (Python 3.14) after the fixes:**
1. Natural `exit` in the shell: child and broker end, tab closes itself.
2. Child killed from outside: tab closes itself, no traceback.
3. Kill Session (`ai_terminal_kill_session`): session ends, tab stays, notice `[session killed -- transcript kept, tab not closed]`.
4. End Session (`ai_terminal_end_session`) on a live tab: session ends, tab closes.
5. End Session on an already-dead tab: tab closes cleanly.
6. Detach 1: Close Tab Keep Session Alive (`ai_terminal_close_keep_alive`), then Recover Session: session survives, history replayed, typing works.
7. Detach 2: plugin reload with live tabs (touch the file's mtime): all tabs reattach with history.
8. Detach 3: hand-off of one tab to Windows Terminal (`ai_terminal_open_in_windows_terminal`), then Recover Session: first FAILED, passes after 7076fcc.
9. Detach 4: `ai_terminal_detach_all_to_windows_terminal` then `ai_terminal_reattach_all_from_windows_terminal`: two sessions (this Claude session and a test shell) moved and came back, relays gone, brokers alive.

**Bugs found and fixed (all pushed to GhostShell origin/main):**
- `0a325bd` THE auto-close bug. The broker ends a session by disconnecting the tab's output pipe; the tab's read then fails with WinError 233, and Python 3.14's asyncio read-pipe `_force_close` raises `AttributeError: ... '_empty_waiter'` and never calls `connection_lost`, so `_reader_finished` never ran and the tab never closed. Fix: set `_read_transport._empty_waiter = None` in `_BrokerPty.astart` (guarded by hasattr). The console held the traceback; the code in the older thread client never hit this path (the thread-free client came in today, 4c59f86). Earlier wrong guesses of mine: that Claude was slow to exit (it exited at once), and reading the session text log (it is closed BEFORE the "[process exited]" notice is written, so its absence proves nothing).
- `30977dd` the notice `[closed -- session kept alive, still running]` was printed on a plugin reload even when the session had already ended. Now checks the broker's record file (the broker deletes it on exit): gone means `[tab detached -- the session had already ended, tab kept]`. The "ended" branch was not reproducible live after 0a325bd.
- `9464b24` removed the blanket close block (Ctrl+W, tab X, `close_by_index` did nothing on any ai_terminal tab, even dead ones; only End Session closed them). His words: "just use your wisdom ... I don't need any blocks"; see sublime-mcp memory never-close-own-tab-no-blocks-2026-10-15. A plain close now DETACHES the session (it keeps running, recoverable); it does not kill it, despite older docstrings saying it does. The opt-in `tab_close_input` graceful-exit flow stays but no profile uses it (it is dead weight; I left it, he had no opinion).
- `7076fcc` (a) Move to Windows Terminal raised a native approval dialog: removed. (b) Recover Session on a session still held by a Windows Terminal relay: for a stale local terminal object it skipped the busy check, connected into the busy pipe and the error said the session was "gone", leaving an empty tab. Now it sends the broker `DISCONNECT` (as Reattach All already did) via the new `_release_pipe_async`, waits for the slot, then attaches; a busy pipe is reported as busy; the picker row reads "busy in another window -- picking it takes it over".
- `b4cc9f0` List Sessions listed ended sessions as "orphaned" rows with no PID (four seen): it always added gc-retained `_Terminal` objects with no broker record. Now skipped when broker discovery worked and the object has no open tab (Recover Session already did this).

- `32cec64` (second half) Recover Session was EMPTY for a tab that had died while keeping its view (his report after my own tab died in a failed replay; List Sessions showed it, clicking restored it). `_show_choices` skipped any session whose term had a valid, windowed view, even with a dead client. Now such a tab counts as attached only if `term.pty.is_alive()`. Side effect found and fixed in the same commit: several `_Terminal` objects can exist per session (the registered one plus old ones the gc scan finds after a plugin reload); the dict kept the LAST, so a healthy tab was listed as "busy in another window" and picking it would have disconnected the live tab (I cancelled the picker in time); the dict now prefers the object whose connection is alive. Proved: healthy tab not listed, detached test session listed and recovered with history and typing. NOT reproduced live: the exact open-tab-with-dead-client state (it rests on the code change).

**LESSON (my own tab died, he had to recover it):** GhostShell's repo IS the live package in the main Sublime, so every Edit/Write save reloads the plugin and reattaches this session's tab. I once saved call sites that used `_replay_feed` before the method existed; the reload ran a replay, hit the missing method and killed my tab. Rule: make every save self-consistent: add new methods/constants first, switch callers last, and never split one change across saves where an intermediate state would fail at import or during a replay. Do risky multi-step edits in a copy and copy the finished files in.

- TESTED ON THE 3.8 PORTABLE LATER THE SAME DAY (his order "test it on the 3.8 portable"): D:\st_portable_4200, a `git archive` copy of b4cc9f0 plus ghostty-vt.dll in its Data\Packages, MCP reconnected with `/mcp reconnect sublime-mcp-portable-4200` typed into my own tab. ALL PASS on the Python 3.8 host: typing, natural exit (tab auto-closes, no traceback: the 0a325bd fix works on 3.8), external kill (auto-closes), Kill Session (tab kept, `[session killed ...]`), End Session on a live and on a dead tab, Close Keep Alive + Recover, plugin reload, hand-off to Windows Terminal + Recover takeover, detach all + reattach all, List Sessions shows no phantom rows. TWO BUGS seen on 3.8, FIXED in 32cec64 (his ruling: "any repeated banner or overwritten text we have to classify as bugs"; I had wrongly called them cosmetic). Cause: width, not Python 3.8. The broker's saved output mixes screen draws made at different widths (ConPTY repaints with ESC[H and absolute positions) and the tab replayed all of it at one fixed width. Reproduced on the 3.8 portable by spawning a tab at 94 columns, narrowing the portable's window to about 21 columns (`resize_window` width 560) and reloading: 3 banners before, 1 after. Fix: the broker writes a private OSC `ESC]777;GhostShellResize;cols;rows BEL` into its saved output at start and at every ConPTY resize (never to a live client; `_resize_marker`, `_Pty.on_resize`), and the tab applies each size to its parser during a reattach replay (`_BrokerPty._replay_feed`, `_Terminal._on_replay_resize`), then restores its real size before `finish_bootstrap`. Old brokers write no markers (behave as before). Proved on 3.8 (narrow reload clean) and on 3.14 (reload keeps history, typing works).

**Procedure facts that worked (reuse):** commands that take `group` and `index` (kill_session, end_session, close_keep_alive) can be aimed at an exact tab, so no typing into the wrong tab; verify the target by `get_active_file` content (a Claude tab shows a Session ID) before any `send_string`; a native dialog blocks the main thread and `list_native_windows` + `dismiss_native_window action=ok` answer it; commit messages with quotes must go through `git commit -F <file>` in PowerShell 5.1 (a here-string with double quotes broke the arguments once, nothing was committed). Saving a plugin file reloads it in the live Sublime and reattaches this session's own tab, which worked every time.
